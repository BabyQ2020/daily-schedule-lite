## 3. 长期任务服务新增接口

```ts
setArchived(taskId, { archived, expectedUpdatedAt }, deps?): Promise<LongTask>
softDelete(taskId, { expectedUpdatedAt }, deps?): Promise<LongTask>
restore(taskId, { expectedUpdatedAt }, deps?): Promise<LongTask>
purge(taskId, { expectedUpdatedAt }, deps?): Promise<{ task: number; versions: number; exceptions: number }>
listDeleted(page?, deps?): Promise<PagedResult<LongTaskAggregate>>
```

- 全部委托 Repository（S2.2 已实现的事务与乐观锁），服务只注入 `now`/`today`。
- `listDeleted` 固定 `deleted: 'deleted'`、`archived: 'all'`、按 `updatedAt` 倒序，返回聚合（含 `issues`，便于 UI 提示历史异常）。
- `purge` 返回条数，供 UI 展示「已删除 1 个任务、N 个版本、M 条例外」。

## 4. 普通任务服务

```ts
softDeleteTasks(ids, deps?): Promise<number>
restoreTasks(ids, deps?): Promise<number>
purgeTasks(ids, deps?): Promise<DeleteTasksResult>
listDeletedTasks(page?, deps?): Promise<PagedResult<Task>>
```

- 复用 `repositories/tasks.ts` 的软删除/恢复/彻底删除：软删除只写 `deletedAt` 与 `updatedAt`，不动 `dailyPlans` 与 `workLogs`；彻底删除才摘除计划勾选、把日志 `taskId` 置空并保留标题快照。
- `listDeletedTasks` 固定 `deletion: 'deleted'`、`archived: 'all'`——回收站必须显示「删除前已归档」的任务，否则用户会以为数据丢了（首轮测试即因此失败，已修）。

## 5. 统计口径：软删除一律排除

新增唯一判定 `isDeletedTask(task)`（`deletedAt !== null && !== undefined`，兼容历史 `undefined`），并在以下位置收口：

| 位置                                                          | 变化                                           |
| ------------------------------------------------------------- | ---------------------------------------------- |
| `progress.isCountedTask` / `accumulateProgress` / `isOverdue` | 已删除任务不计入进度分母、不计逾期             |
| `project-progress.loadProjectProgress` / `loadTaskOverview`   | 流式累加与总览跳过已删除                       |
| `health.loadProjectHealth`                                    | 项目分桶跳过已删除，健康度不再因回收站任务报警 |
| `today.isOpenTask` / `loadTodayBoard`                         | 今日计划、逾期、待结转、今日完成均排除         |
| `period-stats.loadPeriodStats`                                | 计划数、完成数、逾期、待结转、新建数均排除     |

字段语义仍为 `deletedAt > archivedAt > 生命周期`：已删除任务即使仍挂了计划或仍处于暂停，也不出现在任何活动视图与统计中。

## 8. 与设计的差异

| 项                 | 设计             | 实施                                           | 理由                                                 |
| ------------------ | ---------------- | ---------------------------------------------- | ---------------------------------------------------- |
| 长期任务回收站查询 | 未指定返回形态   | 返回 `PagedResult<LongTaskAggregate>`          | 回收站后续要展示规则数与历史异常，聚合比裸记录更有用 |
| 普通任务服务       | 未定义服务层     | 新增 `services/tasks/service.ts`（仅删除语义） | S4 需要服务边界；CRUD 仍留页面，S7 统一收敛          |
| 统计排除           | §10 表列「排除」 | 5 个统计模块统一收口                           | 设计语义落地，非范围扩张                             |
| 恢复约束           | 只清 `deletedAt` | 同左，不改 `archivedAt`、不追加事件            | 无差异                                               |
