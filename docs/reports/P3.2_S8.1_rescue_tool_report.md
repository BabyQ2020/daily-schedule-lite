## 2. 安全设计（代码层面强制）

| 风险               | 措施                                                                                                     |
| ------------------ | -------------------------------------------------------------------------------------------------------- |
| 打开即建库         | 先用 `indexedDB.databases()` 确认存在；不存在直接提示，不调用 `open`                                     |
| 版本不符触发升级   | `open(name, 当前版本)` 显式指定；`onupgradeneeded` 内立即 `transaction.abort()`，并关闭连接              |
| 意外写入           | 只使用 `readonly` 事务；页面内**没有任何** `add / put / delete / clear` 调用（测试用正则强校验）         |
| 被其他标签页占用   | `onblocked` 立即失败并提示关闭其他页面                                                                   |
| 读取期间版本被变更 | `onversionchange` 关闭数据库并让本次导出失败                                                             |
| 无限等待           | 检测 5s、打开 8s、读取 10s 三段超时，失败即清理定时器并进入单一终态                                      |
| 误当备份导入       | 信封 `format` 为 `daily-schedule-lite/rescue-snapshot`，与可导入的 `daily-schedule-lite/backup` 明确区分 |

页面同时展示 11 张表的行数，导出前可肉眼核对。

## 3. 自动化验证（8 例）

| 用例           | 断言                                                                                |
| -------------- | ----------------------------------------------------------------------------------- |
| 库不存在       | `exists=false`，且 `databases()` 中不出现该库（不会顺手建库）                       |
| 库存在         | 返回原始 IDB 版本号，与 `databases()` 一致                                          |
| 正常打开       | 按检测到的版本打开成功，`db.version` 与检测值一致                                   |
| 读取行数       | `tasks=2`、`meta=1`，数据与写入一致                                                 |
| 读取不改数据   | 关闭后用新连接重读，行数与字段不变                                                  |
| 版本高于库     | 触发 `upgradeneeded` → 中止 → 报错；库版本保持原值（未升级）                        |
| 检测后库被删   | 打开被拒，`databases()` 中仍无该库（未创建空库）                                    |
| 信封与静态约束 | `format` 非 backup；`TABLES` 11 项；脚本只含 `'readonly'`，无写 API、无 `readwrite` |

关键发现（已写入测试注释）：**Dexie 的 `version(1)` 在 IndexedDB 里是 version 10**。救援页必须使用 `databases()` 返回的原始版本号，不能用 Dexie 的逻辑版本号，否则会触发 `VersionError` 或误升级。测试因此全部以检测值打开。

## 5. 与设计的差异

| 编号 | 设计                                           | 实现                                                  | 原因                                                                 |
| ---- | ---------------------------------------------- | ----------------------------------------------------- | -------------------------------------------------------------------- |
| D1   | 独立 `tools/rescue-export.html` + 独立 JS 模块 | 单文件内联脚本，核心逻辑挂在 `window.__RESCUE_CORE__` | 救援工具必须在主应用资源损坏时仍可用，不依赖构建产物                 |
| D2   | 状态机 `idle→…→done/failed`                    | 用 `settled` 标志 + 三段超时实现等价语义              | 页面规模小，无需状态机库                                             |
| D3   | 导出 JSON 含 schema 版本                       | 导出 `dbVersion`（原始 IDB 版本）与表计数             | 救援快照只供人工核对，不作为迁移输入；`schemaVersion` 由备份格式承载 |

## 6. 真实浏览器验证（V1–V6）

`npm run build` + `npm run preview` 后执行 `npm run verify:rescue`（独立 profile，用后删除，不触碰日常浏览器数据）。

| 项          | 结果         | 证据                                                                                                          |
| ----------- | ------------ | ------------------------------------------------------------------------------------------------------------- |
| V1 库不存在 | 通过         | 全新 profile 下 `detect` 返回 `exists=false`，随后 `indexedDB.databases()` 中仍无该库（未建空库）             |
| V2 正常读取 | 通过         | 应用启动后 `detect` 返回 `version=20`（Dexie v2 ×10，原始 IDB 版本），11 张表全部命中，两次读取行数一致       |
| V3 被占用   | **未自动化** | `blocked` 只在「另一连接不响应 versionchange」时出现，需要人为制造不配合的占用页；列入手工清单                |
| V4 版本变更 | 通过         | 救援连接持有期间发起 `open(name, version+1)` → 升级成功；旧连接随即关闭，`transaction` 抛 `InvalidStateError` |
| V5 版本更高 | 通过         | `openExistingReadonly(name, version+1)` 被拒；随后 `detect` 版本不变（未升级、未建库）                        |
| V6 信封身份 | 通过         | `format = daily-schedule-lite/rescue-snapshot`，`dbVersion` 与检测值一致                                      |

脚本输出（节选）：

```
ok   V1 库不存在时 detect 返回 exists=false
ok   V1 检测后未创建空库
ok   V2 打开应用后数据库已创建
ok   V2 库版本为 Dexie v2（原始 IDB 版本 20）
ok   V2 只读读取 11 张表（TABLES 中 11 张命中）
ok   V4 版本变更后旧连接已关闭，拒绝继续读取
ok   V5 版本高于库时拒绝打开（不升级）
ok   V6 信封 format 为 rescue-snapshot
全部验收项通过
```

**V3 的手工确认方式**：打开两个标签页，其中一个通过 DevTools 的 Application 面板保持数据库连接不关闭，再在另一个标签页用更高版本打开；救援页应给出「数据库被其他标签页占用」而不是卡死或误升级。
