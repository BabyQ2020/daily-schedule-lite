## 3. Repository 接口实际签名

```ts
createLongTask(input: LongTaskCreateInput, context: CreateContext = {}, database: WorkbenchDatabase = db): Promise<LongTaskAggregate>
updateLongTaskInfo(id: Id, patch: LongTaskInfoPatch, context: WriteContext, database = db): Promise<LongTask>
appendLongTaskRuleVersion(id: Id, input: LongTaskRuleVersionInput, context: WriteContext, database = db): Promise<{ task: LongTask; version: LongTaskRuleVersion }>
appendLongTaskException(id: Id, input: LongTaskExceptionInput, context: WriteContext, database = db): Promise<{ task: LongTask; exception: LongTaskException }>
revokeLongTaskException(id: Id, input: LongTaskExceptionRevokeInput, context: WriteContext, database = db): Promise<{ task: LongTask; exception: LongTaskException }>
appendLongTaskLifecycleEvent(id: Id, input: LongTaskLifecycleInput, context: WriteContext, database = db): Promise<LongTask>
reopenLongTaskWithRuleVersion(id: Id, input: LongTaskReopenInput, context: WriteContext, database = db): Promise<{ task: LongTask; version: LongTaskRuleVersion }>
setLongTaskArchived(id: Id, archived: boolean, context: WriteContext, database = db): Promise<LongTask>
softDeleteLongTask(id: Id, context: WriteContext, database = db): Promise<LongTask>
restoreLongTask(id: Id, context: WriteContext, database = db): Promise<LongTask>
purgeLongTask(id: Id, context: WriteContext, database = db): Promise<{ task: number; versions: number; exceptions: number }>
```

上下文类型：

```ts
interface WriteContext {
  expectedUpdatedAt: string;
  now?: string;
  today?: string;
}
interface CreateContext {
  now?: string;
  today?: string;
}
```

输入类型（`LongTaskCreateInput` / `LongTaskInfoPatch` / `LongTaskRuleVersionInput` / `LongTaskExceptionInput` / `LongTaskExceptionRevokeInput` / `LongTaskLifecycleInput` / `LongTaskReopenInput`）均只暴露业务字段；`versionNo`、`revision`、`previousRevisionId`、`baseOccurrence`、`before`、`after`、`updatedAt`、`createdAt` 全部由仓储在事务内推导。

## 4. 各写接口的事务范围

| 接口                                                             | 事务 | 表                                                  |
| ---------------------------------------------------------------- | ---- | --------------------------------------------------- |
| `createLongTask`                                                 | `rw` | longTasks、longTaskRuleVersions                     |
| `updateLongTaskInfo`                                             | `rw` | longTasks                                           |
| `appendLongTaskRuleVersion`                                      | `rw` | longTasks、longTaskRuleVersions                     |
| `appendLongTaskException`                                        | `rw` | longTasks、longTaskRuleVersions、longTaskExceptions |
| `revokeLongTaskException`                                        | `rw` | longTasks、longTaskRuleVersions、longTaskExceptions |
| `appendLongTaskLifecycleEvent`                                   | `rw` | longTasks                                           |
| `reopenLongTaskWithRuleVersion`                                  | `rw` | longTasks、longTaskRuleVersions                     |
| `setLongTaskArchived` / `softDeleteLongTask` / `restoreLongTask` | `rw` | longTasks                                           |
| `purgeLongTask`                                                  | `rw` | longTasks、longTaskRuleVersions、longTaskExceptions |

约束：一个事务只操作一个长期任务聚合；读主记录、校验 `expectedUpdatedAt`、读关联历史、领域校验、计算、写入全部位于同一事务内；事务内不等待非 Dexie 异步；`ConstraintError` 只在事务外新开只读事务诊断，随后统一抛 `ConflictError`。

## 5. `expectedUpdatedAt` 与 `updatedAt` 实现

- 乐观锁：事务内 `database.longTasks.get(id)` 后做字符串全等比较；不等即 `ConflictError('该长期任务已被其他操作修改，请刷新后重试。')`；不存在抛 `NotFoundError('长期任务')`；软删除任务在普通写入口以 `ValidationError('该长期任务已删除，请先恢复。')` 拒绝。
- `updatedAt` 一律调用 `src/repositories/shared.ts` 的 `nextUpdatedAt(previous, now)`，取 `max(now, previous + 1ms)`，不复制实现、不使用浮点。
- `now` 由 `context.now ?? nowISOString()` 注入；注入更早时间不会让 `updatedAt` 倒退（有测试）。
- 幂等接口（归档/软删/恢复）在目标状态已满足时直接返回当前记录，不写库、不推进 `updatedAt`。

## 6. reopened + 新规则版本原子性验证

- `reopenLongTaskWithRuleVersion` 在单个 `rw` 事务内同时写入 `reopened` 事件与新规则版本；`effectiveFrom` 默认等于 `date`，显式指定时不得早于 `date`。
- 计算 `hardStop` 时使用 `minIso(task.endDate, until)`，**排除 ended-1**，避免重开后的新版本被旧结束边界截断；`count` 不重置。
- 验证用例：
  - `同一个事务写入 reopened 与新版本`
  - `版本写入失败时 reopened 事件也不存在`（对 `longTaskRuleVersions` 注入 creating 失败）
  - `主记录写入失败时新版本一起回滚`（对 `longTasks` 注入 updating 失败）
  - `count 不重置：重开后的槽位继续累计`（ended 次日重开，槽位 19 → 22–25，`slotIndex` 连续 1–5）

## 7. 例外修订链验证

- 追加时仓储自行推导：`revision = 链尾 + 1`、`previousRevisionId = 链尾 id`、`baseOccurrence = slotOn(剔除当日例外后的原规则槽位)`、`before = 当前有效状态`、`after = 新状态`。
- `initial` 只允许未来日期；过去日期必须已存在历史记录，且只能走 `correction` 并带 `reason`。
- `revocation` 的 `after` 恒为 `{ mode: 'rule' }`；当前状态已是 `rule` 时重复撤销抛 `ConflictError('该日期已恢复原始规则安排，无需再次撤销。')`。
- 覆盖用例：首版 skip/override、correction 追加并保留 before/after、缺原因/过去首版/非槽位日期拒绝、撤销后可再次修正、失败整体回滚。

## 8. 持久化阶段异常注入与回滚结果

所有注入均使用 Dexie hook（`hook('creating'|'updating').subscribe(handler)`，第 n 次抛错；`unsubscribe(handler)` 在 `finally` 清理），断言在事务结束后用新的只读事务重读：

| 场景                   | 注入点                          | 结果                         |
| ---------------------- | ------------------------------- | ---------------------------- |
| 创建：首版规则写入失败 | `longTaskRuleVersions.creating` | 主记录不存在                 |
| 规则版本追加失败       | `longTaskRuleVersions.creating` | 版本数不变、`updatedAt` 不变 |
| 例外写入失败           | `longTaskExceptions.creating`   | 例外链不变、`updatedAt` 不变 |
| 生命周期写入失败       | `longTasks.updating`            | `events`、`updatedAt` 均回滚 |
| 重开：版本失败         | `longTaskRuleVersions.creating` | `reopened` 不存在            |
| 重开：主记录失败       | `longTasks.updating`            | 新版本不存在                 |
| 彻底删除中途失败       | `longTaskExceptions.deleting`   | 三表记录全部保留             |

## 9. 并发测试结果与环境限制

- 用例：`两次并发基本信息修改只有一次成功`（乐观锁）、`不同长期任务的写入互不影响`；另有 `并发写入同一生效日只会成功一次`（唯一索引冲突路径）。
- 环境限制：测试运行在 fake-indexeddb + Dexie 上，同一事件循环内的 `Promise.all` 只验证**事务串行化与乐观锁语义**，不等价于真实浏览器多标签页争用；真实并发未验证（沿用 S2.1 的同类限制声明）。

## 13. 与 P3.1 v1.3 冻结设计的差异

| 项                   | 设计                      | 实施                                         | 说明                                            |
| -------------------- | ------------------------- | -------------------------------------------- | ----------------------------------------------- |
| 创建时的历史基准     | R1 要求生效日不早于 today | 首版校验基准取 `min(today, startDate)`       | 为支持「补录已开始的历史系列」；其余版本仍按 R1 |
| 重开 `effectiveFrom` | 默认等于重开日            | 同左，显式值早于重开日拒绝                   | 无差异                                          |
| 撤销返回             | 返回新例外记录            | 同左                                         | 无差异                                          |
| 彻底删除返回         | 删除条数                  | `{task:1, versions, exceptions}`             | 便于核对                                        |
| 错误文案             | 未逐字规定                | 统一中文提示（Conflict/Validation/NotFound） | 语义一致，文案为实施细化                        |
| 例外 `before/after`  | 记录状态                  | 同左，`before` 为当前有效状态                | 无差异                                          |
