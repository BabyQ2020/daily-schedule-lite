## 2. 公开接口

```ts
// 依赖注入：database 可替换，now/today 可注入以便测试
export interface ServiceDeps { database?: WorkbenchDatabase; now?: string; today?: ISODate }

// 7 个写入
createLongTask(input: CreateLongTaskRequest, deps?): Promise<{ id: string }>
updateLongTaskInfoById(taskId, input: UpdateInfoRequest, deps?): Promise<LongTask>
appendRuleVersion(taskId, input: AppendRuleVersionRequest, deps?): Promise<LongTaskRuleVersion>
writeException(taskId, input: WriteExceptionRequest, deps?): Promise<LongTaskException>
revokeException(taskId, input: RevokeExceptionRequest, deps?): Promise<LongTaskException>
addLifecycleEvent(taskId, input: LifecycleRequest, deps?): Promise<LifecycleEvent>
reopenWithRuleVersion(taskId, input: ReopenRequest, deps?): Promise<LongTaskRuleVersion>

// 2 个查询
getAggregate(taskId, deps?): Promise<LongTaskAggregate | null>
listOccurrences(taskId, from, to, deps?): Promise<ResolvedOccurrence[]>
```

请求类型均在各写入输入上增加 `expectedUpdatedAt`（乐观锁），服务原样传给 Repository；`versionNo`、`revision`、`previousRevisionId`、`baseOccurrence`、`before/after` 仍由 Repository 在事务内推导。

## 3. 职责划分

服务只做四件事：

1. **依赖与时钟注入**：`database ?? db`、`now ?? nowISOString()`、`today ?? todayISO()`；所有守卫与 `updatedAt` 使用同一组时钟，避免测试与生产口径分叉。
2. **默认值**：创建时 `startDate` 缺省取 `today`，实现「新建即生效」。
3. **聚合展开**：`listOccurrences` 读取聚合 → `computeSlots(dateUpper = to)` → 按 `from` 过滤 → `resolveOccurrence`（skip 返回 `null` 被剔除）。
4. **错误语义**：查询不存在任务抛 `NotFoundError`；反向区间抛 `ValidationError`；其余错误（`ConflictError`/`ValidationError`）原样透传，不吞错、不重复包装。

明确不做：事务、乐观锁、守卫、唯一索引冲突翻译、子表写入顺序——全部在 Repository（S2.2）内完成，服务不重复实现，也不直接触碰 Dexie 表。

## 4. 事务与一致性

服务不新开事务；每个写调用进入 Repository 的单一 `rw` 事务，事务范围与 S2.2 报告第 4 节一致。因此：

- 「读主记录 → 校验 expectedUpdatedAt → 读历史 → 守卫 → 计算 → 写入」仍是一个原子步骤；
- 重开的 `reopened` + 新版本仍在同一事务内；
- 服务层无法绕过守卫或唯一索引。

## 5. 查询语义

- **计数与窗口无关**：`computeSlots` 始终从系列起点累计槽位，`listOccurrences` 只把结果裁到 `[from, to]`；因此分窗拼接等于整段查询（有专门用例）。
- **skip 不出现在结果中**，但仍占用槽位号（例：19、21 的 `slotIndex` 为 1、3）。
- **override** 应用标题/描述/备注/优先级/截止日/标签，`baseOccurrence` 保留原始安排，便于「仅修改本次」回显。
- **ended 当天起**不再生成；**暂停区间**不生成、恢复后继续；**DECISION-1** 下 `effectiveFrom > reopened.date` 的中间段沿用上一版（有用例）。
