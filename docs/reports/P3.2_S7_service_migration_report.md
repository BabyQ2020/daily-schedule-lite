## 2. 分层规则（本阶段固化）

```
pages / features / components
        │  只允许 import services
        ▼
services（业务语义、默认值、跨仓储编排）
        │
        ▼
repositories（单表/聚合读写、事务、守卫、乐观锁）
        │
        ▼
db（Dexie，11 张表）
```

三条机器可查的约束：

1. **ESLint**：`no-restricted-imports` 禁止页面/特性/组件 import `@/db*` 与 `@/repositories*`；`no-restricted-syntax` 继续禁止 `db.tasks` 这类表访问。
2. **ESLint**：测试文件与 `src/test/**` 关闭上述两条（测试需要直接建库、灌数据）。
3. **约定**：Service 不接收 UI 类型、不返回 React 节点；错误统一抛 `RepositoryError` 子类，由页面 `App.useApp()` 提示。

## 3. 新增服务模块

| 文件                                    | 职责                                   | 主要导出                                                                                                                                                                                   |
| --------------------------------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `src/services/lookups.ts`               | 跨页面下拉数据（项目、标签、任务候选） | `listProjects`、`listTags`、`listTasks`                                                                                                                                                    |
| `src/services/logs/service.ts`          | 工作日志读写                           | `queryLogs`、`getLog`、`createLog`、`updateLog`、`deleteLog`                                                                                                                               |
| `src/services/tasks/service.ts`（重写） | 任务读写 + 回收站                      | `createTask`、`getTask`、`updateTask`、`queryTasks`、`setTaskStatus`、`archiveTasks`、`unarchiveTasks`、`deleteTasks`、`softDeleteTasks`、`restoreTasks`、`purgeTasks`、`listDeletedTasks` |
| `src/services/projects/service.ts`      | 项目、里程碑、风险                     | `createProject`、`updateProject`、`archiveProject`、`deleteProject`、`addMilestone` 等                                                                                                     |
| `src/services/reports/service.ts`       | 报告与快照                             | `createReport`、`updateReport`、`saveReportSnapshot`、`listReportVersions` 等                                                                                                              |
| `src/services/tags/service.ts`          | 标签与使用量                           | `listTags`、`createTag`、`updateTag`、`deleteTag`、`countTagUsage`                                                                                                                         |
| `src/services/today/service.ts`         | 每日计划                               | `getPlan`、`ensurePlan`、`upsertPlan`、`addTaskToPlan`、`removeTaskFromPlan`、`addExtra`、`removeExtra`                                                                                    |

设计取舍：

- **薄封装优先**：Service 当前主要负责默认值、去 db 参数、错误语义收口，不做多余编排，避免与仓储层重复。
- **命名修正**：仓储的 `restoreTasks` 表示「取消归档」，与回收站的「恢复」重名，Service 层改为 `unarchiveTasks`；回收站恢复统一叫 `restoreTasks`。
- **不传 db**：页面不再持有数据库实例，Service 内部使用默认 `db`，测试通过参数注入独立库。

## 6. 行为变化与兼容性

1. `unarchiveTasks` 是新名字，仓储层 `restoreTasks` 保持不变；页面已全部切换，无遗留调用。
2. `services/logs.getLog` 返回 `WorkLog | undefined`（与仓储一致），调用方需处理 `undefined`。
3. 页面不再向仓储传 `db`，测试仍可通过 Service 的参数注入独立数据库。
4. 未改动任何数据库结构、字段语义、备份格式与导出格式。
