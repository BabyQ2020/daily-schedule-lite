## B. 五个写入入口的事务化实现

统一形态（以 `updateTask` 为例）：

```ts
return database.transaction('rw', database.tasks, async () => {
  const stored = await database.tasks.get(id);   // 事务内重新读取当前记录
  ...
  const next = { ...existing, updatedAt: nextUpdatedAt(existing.updatedAt, now) };
  await database.tasks.put(next);               // 同一事务内写入
  return next;
});
```

| 入口                  | 事务范围       | 读取位置         | 计算依据                           | 返回         |
| --------------------- | -------------- | ---------------- | ---------------------------------- | ------------ |
| `updateTask`          | `rw` / `tasks` | 事务内 `get`     | 事务内读到的 `existing.updatedAt`  | 新记录       |
| `archiveTasks`        | `rw` / `tasks` | 事务内 `bulkGet` | 每条记录自身 `updatedAt`           | 命中条数     |
| `restoreTasks`        | `rw` / `tasks` | 事务内 `bulkGet` | 同上                               | 命中条数     |
| `softDeleteTasks`     | `rw` / `tasks` | 事务内 `bulkGet` | 同上；仅 `deletedAt === null` 的行 | 实际变更条数 |
| `restoreDeletedTasks` | `rw` / `tasks` | 事务内 `bulkGet` | 同上；仅 `deletedAt !== null` 的行 | 实际恢复条数 |

要点：

- 无任何「事务外读旧值 → 事务内写」的路径；更新时间只来自事务内读到的记录。
- 批量操作逐条读取、逐条计算，写入在单一事务内 → **中途失败整体回滚**。
- 幂等性保留：无目标行时不写库、返回 0（提前 return 也在事务内）。
- 签名未变：`updateTask(id, patch, database)` 第三参仍是 `database`；`archiveTasks/restoreTasks/softDeleteTasks/restoreDeletedTasks` 的既有 `options` 位置与默认值未变。
- 兼容嵌套：`task-actions.ts` 的 `batchAddTag` 已在外层事务内调用 `updateTask`，Dexie 复用同一事务，不产生嵌套写冲突（全量测试验证）。

## D. 两项并发测试结果

| 测试                                        | 方法                                                 | 断言                                                                   | 结果     |
| ------------------------------------------- | ---------------------------------------------------- | ---------------------------------------------------------------------- | -------- |
| A：同一任务并发两次 `updateTask`            | `Promise.all([updateTask(title), updateTask(note)])` | 两个字段都保留；`updatedAt` 严格大于初值；后完成者严格大于先完成者     | **通过** |
| B：`archiveTasks` 与 `softDeleteTasks` 并发 | `Promise.all([...])`                                 | `archivedAt` 与 `deletedAt` 均为设定值、互不覆盖；`updatedAt` 严格递增 | **通过** |

说明：测试环境是 `fake-indexeddb` + Dexie 4。Dexie 对同 scope 的 `rw` 事务**串行调度**，因此两个并发调用实际按队列执行——这是「事务串行化」而非「串行测试」：调用方确实同时发起，事务边界内各自重新读库，所以第二个事务能看到第一个的结果。若未来引入多标签页，跨连接并发由 IndexedDB 自身的锁保证，仍属同一机制。
